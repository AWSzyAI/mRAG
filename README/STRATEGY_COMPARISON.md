# InfoSeek 集成策略对比分析

## 🎯 问题本质

**核心矛盾**:
- **InfoSeek 特性**: 开放式问题 (1.3M)，无答案标签
- **MRAG-Bench 特性**: 四选一多选题，包含 GT 答案
- **需求**: 如何利用 InfoSeek 的规模来增强 MRAG-Bench?

## 🔍 方案详解

### 方案 A: 转换为多选一 (当前实现)

```
InfoSeek 开放式问题
    ↓
LLM 生成答案 + 干扰项
    ↓
MRAG 格式 {options: A/B/C/D, correct: "A"}
    ↓
MRAG-Bench 评估框架
```

**适用场景**:
- ✅ 想快速积累数据量
- ✅ 需要与基线对标
- ✅ 团队熟悉 MRAG-Bench 框架
- ✅ 时间紧张（1-2周）

**质量保证**:
- SQLite 缓存避免重复转换（降低 API 成本）
- 信心度评分 (0-1) 用于结果过滤
- 人工抽样审核 (建议 100 个样本，由 3 人投票)

**成本估算** (1000 个样本):
- OpenAI API: $0.3-0.5 (gpt-3.5-turbo)
- 人工审核: 5 小时 × $50/hr = $250
- 总计: ~$300

**风险**: LLM 生成质量，尤其是：
- 复杂问题的干扰项不够「合理」
- 特殊领域知识（医学、法律）可能有偏差
- 某些问题可能有多个正确答案

---

### 方案 B: 保持开放式，用语义评分

```
InfoSeek 开放式问题
    ↓
模型生成开放式答案
    ↓
语义匹配评分:
  - BERTScore (推荐)
  - ROUGE / BLEU (备选)
  - LLM judge (GPT-4 评估)
    ↓
开放式 VQA 评估结果
```

**适用场景**:
- ✅ 研究开放式 VQA 问题
- ✅ 想保留原始数据特性
- ✅ 有能力处理「软」评分标准
- ✅ 在乎「合理多答案」的能力

**评分方式对比**:

| 评分方法 | 优点 | 缺点 |
|-------|------|------|
| **BERTScore** | 语义相似度好，快速 | 不考虑多答案有效性 |
| **ROUGE** | 重叠度评估 | 对同义词敏感，需要参考答案集合 |
| **LLM Judge** (GPT-4) | 最灵活，考虑多答案 | 贵 ($0.03/1K tokens)，不可复现 |

**案例**:
```
问题: "What place inflows lake?"

答案变体:
- "river outlet" ✅ 正确
- "outlet river" ✅ 语义等价
- "place where river flows into lake" ✅ 冗长但正确
- "river" ❌ 不完整
- "water source" ❌ 错误

BERTScore 可以给这些不同答案评分
```

**成本估算** (1000 个样本):
- BERTScore: 免费 (本地计算)
- LLM Judge: $30 (如果用 GPT-4)
- 总计: $0-30

**风险**:
- 「正确答案」定义模糊（多个答案都可以接受）
- 评分标准需要校准（什么是 0.8 分 vs 0.9 分？）
- 难以与 MRAG-Bench 基线对标 (评分体系不同)

### 方案 C: 混合方案（部分手工标注）

```
InfoSeek 1.3M 问题
    ↓
分层抽样: 
  - 简单问题 (40%): LLM 转换
  - 中等问题 (40%): 人工标注子集
  - 复杂问题 (20%): 舍去 / LLM + 人工验证
    ↓
混合 GT 集合
    ↓
MRAG 评估 + 开放式评分双轨
```

**适用场景**:
- ✅ 需要高质量 GT（科研出版）
- ✅ 有充足人力（3-5 标注员，3个月）
- ✅ 想同时研究多个评分维度
- ✅ 预算充足

**标注工程**:
- 招募 3-5 个标注员（$15/hr）
- 标注 200-500 个样本
- 质量保证: Cohen's Kappa ≥ 0.8
- 成本: 3000 小时 × $15/hr = $45,000

**预期收益**:
- ✅ 可发表科研论文
- ✅ 资源可开源给社区
- ✅ GT 质量无可批评

## 🎓 不依赖 MRAG-Bench 可行吗？

**完全可行！** 三个替代框架：

### 框架 1: 开放式 VQA 评估 (推荐)

```python
# 评分维度
dimensions = {
    "correctness": 0-1,      # 答案是否正确
    "completeness": 0-1,      # 回答了全部问题
    "clarity": 0-1,           # 表述是否清晰
    "specificity": 0-1        # 是否具体而非模糊
}

# 综合得分
final_score = weighted_avg(dimensions, weights={...})
```

### 框架 2: VQA 指标体系 (学术界标准)

```
准确率 (Accuracy)
    - 完全正确答案的比例
    
BLEU / ROUGE / CIDEr
    - 参考 COCO-QA, VQA v2.0 体系
    
Human 评估
    - 分类评分（1-5 Likert 量表）
```

### 框架 3: 检索增强式评估 (结合 MagicLens)

```
准确率：模型答案是否与 GT 匹配
    ↓
检索准确率: MagicLens 是否检索到相关图像
    ↓
推理链追踪: 模型从图像→ 答案的推理过程是否合理
```

## 🔐 风险缓解

**如果选方案 A (当前实现)，如何保证质量**:

1. **信心度过滤**
   ```python
   # 仅保留高信心度转换
   results = [r for r in converted if r.confidence > 0.8]
   # 预期: 保留 60-70% 数据，但质量更高
   ```

2. **手工审核** (必需!)
   ```
   抽样 200 个样本，3 人投票
   要求: 至少 2/3 同意「干扰项合理」
   如果通过，则 LLM 转换质量可接受
   ```

3. **多轮优化**
   ```
   第一轮: 用基础 prompt 转换
   评估: 测量失败案例
   改进: 优化 LLM prompt 针对特殊问题
   第二轮: 重新转换失败的
   ```
